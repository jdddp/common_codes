# 内部数据资产管理平台

统一存储 / 元数据登记 / 自定义属性 / 检索 / **在线逐帧查看声呐数据**。

- 后端：Python 3.10 + FastAPI + SQLAlchemy 2.0 + SQLite(WAL)，文件本体落磁盘、库内只存索引与属性
- 前端：Vue 3 + Vite + Element Plus（正式界面）；另有**零依赖免构建页**（后端直接托管，装不装 Node 都能用），页内分 **上传 / 数据查询 / 属性管理** 三个分页（顶栏吸顶切换，地址栏记着当前页）
- 解析与渲染：复用现有工程的 5 个 `datareader_*.py` 与无状态算法层，在线播放语义与桌面版 `hdy_viewer.py` 一致
- 部署：单机内网，免登录；不做导出类功能；原始文件下载保留

### 2.1 一键启动（推荐）

双击 `scripts\start.bat`，或在终端执行：

```powershell
scripts\start.bat                       # 就绪后自动打开浏览器（端口取 platform.env，默认 8000）
scripts\start.bat 8080                  # 临时换个端口，只影响这一次
scripts\start.bat 8080 /nobrowser       # 不自动开浏览器
scripts\stop.bat                        # 停止（后端 + Worker），端口同样取 platform.env
scripts\stop.bat 8080                   # 或者直接指定端口
scripts\config.bat                      # 看一眼当前实际生效的配置（端口、数据目录…）
```

**所有配置集中在一个文件里：`platform.env`**（就在本目录下）。改完保存、重启平台即生效——换数据盘、换端口、换 Python 解释器都改它，不用动代码，也不用在每个终端里 `set` 环境变量。详见 §5。

它会依次：**读取 `platform.env` → 幂等初始化数据库 → 后台启动 Worker（最小化窗口）→ 启动后端（独立窗口）→ 轮询 `/api/health` 确认就绪 → 打开浏览器**，并打印访问地址与**实际使用的数据目录**。

- 解释器自动探测：`platform.env` 的 `PYTHON_EXE` → 本机 conda `work` 环境 → PATH 里的 `python`。
- 端口被占用时不会重复启动，而是提示"可能已在运行"并给出 `scripts\stop.bat` 命令。
- 后端日志在标题为 `Platform Backend <端口>` 的窗口里；Worker 日志在被最小化的 `Platform Worker` 窗口里。
- `.bat` 脚本**保持纯 ASCII 内容**（含中文的批处理在 cmd 里会被错误解析，见 §10）；中文说明只在本 README 里。`platform.env` 里的中文注释不影响批处理，它只读 `PYTHON_EXE` / `BIND_HOST` / `BIND_PORT` 三个键。

### 2.3 Linux / 服务器部署

后端和后台任务**本身就是跨平台的**，Linux 上用 `scripts/*.sh`（和 `.bat` 一一对应）。**共用同一个 `platform.env`**，只是路径写法要换：

```bash
# 1) 装依赖（建议用 venv；服务器上把 opencv 换成 headless 版，见下）
python3 -m venv venv
./venv/bin/pip install -r backend/requirements.txt

# 2) 改 platform.env：把三行数据目录改成 Linux 写法
#      STORAGE_ROOT=/srv/data_platform/storage
#      DB_PATH=/srv/data_platform/data/platform.db
#      CACHE_DIR=/srv/data_platform/cache

# 3) 启动
chmod +x scripts/*.sh      # 只需做一次
scripts/config.sh          # 先确认生效的是哪套配置
scripts/start.sh           # 无参数，端口取 platform.env
scripts/stop.sh            # 同样无参数
```

| 脚本 | 作用 |
| --- | --- |
| `scripts/start.sh [port] [--foreground]` | 建库 → 后台起 Worker → 后台起后端 → 等健康检查。`--foreground` 让后端跑在当前终端，**Ctrl+C 会连 Worker 一起停掉** |
| `scripts/stop.sh [port] [--all]` | 按 pid 文件停进程，再兜底释放端口。`--all` 连丢失 pid 文件的流浪 Worker 一起杀 |
| `scripts/config.sh [键]` | 看实际生效的配置，每项标了来源 |
| `scripts/serve.sh` | 只跑后端（前台），systemd 用的就是它 |

日志和 pid 文件在 `scripts/../run/`（`backend.log` / `worker.log` / `*.pid`，启动时自动创建）。

**常驻服务**用 `deploy/` 里的 systemd 单元：

```bash
sudo cp deploy/data-platform-*.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now data-platform-worker data-platform-backend
sudo systemctl restart data-platform-backend      # 改完 platform.env 之后
journalctl -u data-platform-backend -f            # 看日志
```

单元文件头部写了完整的安装步骤（建用户、建 venv、改路径）。**故意没有 `EnvironmentFile=`**——Python 自己会读 `platform.env`，配置仍然只有一个地方要改。

> **两个服务器上必踩的坑**
> 1. **`import cv2` 报 `libGL.so.1: cannot open shared object file`**：服务器没有图形库。换成 `pip install opencv-python-headless` 即可，模块名仍是 `cv2`，代码不用改（实测：普通 `opencv-python` 在无 GUI 的 Ubuntu 上确实导入失败，装 headless 后正常）。
> 2. **`.sh` 必须是 LF 行尾**。从 Windows 拷过去如果变成 CRLF，会报 `$'\r': command not found`。本仓库里的 `.sh` 都是 LF；如果你自己新建，编辑器里选 LF 或 `dos2unix scripts/*.sh`。

## 3. 首次使用流程

> **免构建页顶部有三个吸顶分页**：**上传**（左栏选文件与服务端导入上下挨着，右栏是给两者共用的关联属性面板，滚动时吸附跟随；**面板最上面一行是内置「日期」，预填当天、可改成实际作业日期**）／**数据查询**（检索、属性条件、列表分页、在线查看、下载；属性条件里选中「日期」会变成「从 / 到」两个日期框）／**属性管理**（属性库增删查，「日期」标「（内置）」不可删）。地址栏 `#/upload`、`#/query`、`#/attrs` 记着当前页，刷新或把链接发给别人会停在对应页面；切页只是隐藏/显示，**查询条件、分页进度、已填的取值全都保留**。「新建属性…」卡片固定在导航下方，三个页面都能唤起，但在哪一页建、建完就接到哪一页（属性管理页只建、不自动往上传/筛选里加）。

1. **进数据**（两种方式，都会后台自动解析）：
   - 浏览器上传：「上传」页「上传文件」→ 选择文件/整目录，支持多文件（保留层级）、8MB 分片、断点续传、内容去重（同内容只存一份）；Vue 界面在「文件检索 → 上传文件」。
   - **服务端导入**：「上传」页「服务端导入」（Vue 界面「文件检索 → 服务端导入」），把数据盘上已有的大文件/目录直接登记进来（默认复制、原文件保留；同内容自动复用）。*存量 250MB 级文件推荐用这个，不必再走浏览器。*
2. **看内容**：「数据查询」页列表里点「在线查看」→ 进入双栏查看器（灰度原图 / 算法+伪彩）。
3. **打属性与检索**：属性就是**名称 + 值**——属性库里存的是**可复用的属性名**，**值一律按文本存**（没有类型概念），在每次上传/登记、每次检索时按需填写（**填值时可以直接从"库里已有的取值"里挑**，不必手敲）。三种用法：
   - **按模板**：建模板（可设必填与默认值）→ 上传/导入时自动加载字段；
   - **从属性库多选添加**：上传页/文件详情页点「从属性库添加」（可多选）挑已有属性名；检索页点「从属性库批量添加」一次加多条条件；
   - **库里没有就新建**：点「新建属性」**只填名称**（值不在这里填），保存后**属性名会保留在属性库**，之后上传与检索直接复用；同名即同一个属性，已存在时自动复用、不覆盖原定义。
   检索页按属性组合筛选（条件之间是"并且"，值全部按字符串比较），普通属性的写法只有一种：**`属性名=值`**（"等于"）。`!=`、`like:`、`in:`、`>`、`<` 这些写法都已取消（它们属于"比较符"概念，现在只剩"等于"），写成 `海域!=东海` 会因为属性名里带 `!` 而查不到这个属性、直接报 422。**例外只有内置的「日期」**：它支持**时间范围** `日期>=2026-10-01` / `日期<=2026-10-31`（两条一起就是"之间"），页面上直接给「从 / 到」两个日期框；普通属性想用 `>=` 同样是 422。
4. **维护属性库**：「属性管理」页列出所有属性名与**使用条数**；没有任何取值的属性可以直接删除，已被文件用过的属性禁止删除（先清掉文件上的该属性值）。Vue 界面在「属性与模板」。

### 3.1 属性的用法：名称即标识、值每次填

- **属性库只存"名称"**：名称就是标识（同名即同一个属性），值一律按文本保存——没有类型、单位、枚举项这些概念。属性名里不能出现 `=`（筛选条件里用它分隔属性名和值），长度不超过 100；`!` 不再是分隔符，可以正常出现在属性名里。

- **唯一的内置属性「日期」（v1.8）**：平台自动建立，**不可删除（409）、不可改名（422）、不可重复创建**，属性管理页里标「（内置）」。它的值是**真实日期**——写入时统一归一成**定宽的 `YYYY-MM-DD`**（`2026/10/19`、`2026.10.19`、`20261019`、`2026-10-19 09:30:00` 都会转成 `2026-10-19`；`2026-02-30`、`乱写` 一律 422，脏值进不了库）。正因为它保证是定宽 ISO 文本，**字典序就是时间序**，所以它是**唯一能按时间范围筛选的属性**——不需要引入时间类型列，普通字符串比较就是正确的时间比较。上传页右栏最上面有一行日期框，**预填当天、可改成实际作业日期，留空则本次不提交**；它**不进复选框清单**（内置属性不用勾，也就没有"勾没勾上"的歧义），**「复用上次」也不会带上它**——日期表示"这一批是哪天的"，把上一批的旧日期带过来是最危险的陈旧值，而控件每次打开本来就预填当前日期。每条数据只有**一个**时间概念、由上传者自行组织，页面不另设"上传时间范围"（后端既有的 `uploaded_from`/`uploaded_to` 只作接口参数保留）。
- **值跟着文件走**：每次上传 / 导入 / 单文件编辑时按需填写，互不影响；下次再关联同一个属性时输入框是空的（不会被上次的值带出来）。数字、布尔也可以填，但一律当文本存（`45.5`、`true`）。
- **值可以直接选，不必手敲（上传/导入也一样）**：填取值时，同一个属性**在库里已经出现过的取值**会作为候选列出来（按出现次数降序，带条数提示），点一下即可填入；这只是"建议"，仍然可以手动输入新值——**没有的直接手输，本次填过之后它就成为下次的候选**。候选来自 `GET /api/attributes/values`，所以**免构建页的关联属性（上传与服务端导入共用）/筛选条件、Vue 的上传与文件详情、Vue 的筛选条件**都能直接挑。免构建页把候选**直接列成输入框下方一排可点的链接**（原生 `<datalist>` 只是隐藏式建议，不好找），没有候选时会明说"暂无已有取值：直接手输"；输入框本身也带提示。新增/删除文件或改动属性值后，候选会自动刷新，且**刷新不会清掉正在填的内容**（下拉打开时也会重取）。
- **上传时关联多个属性**（免构建页「关联属性」、Vue 上传弹窗）：
  1. **免构建页：属性面板固定在「上传」页右栏（给左栏的上传与服务端导入共用），里面是属性库复选框列表，勾一下即关联、取消勾一下即移除**——一次点一下就完成，**不用按 Ctrl/Shift，也不用再点「添加所选属性」**；右边立即出现取值框；留空的属性不会提交；属性达到 6 个时自动出现搜索框（平时不占地方）。Vue 上传弹窗仍是「从属性库添加」多选弹层（勾好后一次性"添加"）；
  2. **「复用上次」**：每次上传/导入都用同一批属性时，点一下把上一次**真正提交过的属性连名字带值**一起带出来；预填值标**橙色**提醒"这是上次的值，先确认再上传"，只要改一下（含清空）就变回正常色、不再算预填。记录存在浏览器 localStorage（不经过后端），属性库里已删掉的名字会跳过并在提示里说明；一条带属性的记录都没有时按钮是禁用的；
  3. 选了属性模板时，模板字段自动带出（**仅 Vue**）；**模板字段与手动添加的属性合并显示**（按名称去重）；
  4. 库里没有想要的 →「新建属性…」只填名称 → 保存后**该属性进入属性库**，并自动加入本次关联；
  5. 同名已存在 → 自动复用（不会产生重复属性）。
- **筛选时关联多个属性**（检索页「属性条件」）：「＋ 添加属性条件」逐条加，或「从属性库批量添加」一次勾选多个；条件之间是"并且"；库里没有的也能「新建属性…」建好后立刻作为条件使用；**取值控件是"可选已有值 + 允许手输新值"的下拉**（免构建页是输入框 + 原生下拉建议），选择已有取值即可直接筛选。普通属性的运算符只有一个：`等于`（写法 `属性名=值`，条件之间是"并且"）。**选到内置「日期」时，那一行会自动变成「从 / 到」两个日期框**：两端都填就是"之间"，只填一端就是单边限制（`日期>=…` 或 `日期<=…`），两端都留空则该条件不参与筛选；条件照旧和其它属性条件一起按"并且"求交。
- **服务端语义**：`POST /api/attributes/resolve` 收 `{"names": ["航次","海域"]}`，是"取或建"（幂等，返回 `created` / `existing`）；`/api/uploads/init` 与 `/api/import` 带 `auto_create_attributes=true` 时，未定义的属性名自动补建（**只建名称，不猜类型**）；`PUT /api/files/{id}/attributes` 带 `create_missing=true` 时同理（默认仍忽略未知属性名并在 `ignored_names` 里回报）。
- **删除属性**：`DELETE /api/attributes/{id}`；有任何取值时返回 409 `该属性已有 N 条取值，禁止删除`。
- **老库自动升级**（v1.6）：v1.5 及更早的库（属性带 key/类型/单位、值按类型分列）在服务启动时自动迁移——显示名变成属性名（重名自动加后缀）、四列取值折算成文本（整数浮点去掉 `.0`、布尔变 `true`/`false`、空值不落行）、原 id 保持不变，模板字段引用不受影响。升级是幂等的，不需要手工改库。

### 3.2 关于"数据集"：它是普通属性，不是内置实体

- 平台**没有内置的"数据集"字段**：不再有数据集下拉、数据集表、分类/标签字典。文件在库里是一张平铺的清单，"数据集/航次/海域/类别"这类归属信息**和其他属性完全一样**——你在属性库自建一个属性名（比如 `数据集`、`航次`、`海域`），上传时填值、检索时按该条件筛。
- 免构建页的「上传」与「服务端导入」都直接使用上传卡片里「关联属性」的值；Vue 界面在「文件检索」页用「上传文件 / 服务端导入」弹窗。
- 想按归属分组查看时，检索页加一条属性条件即可（例如 `数据集=2026春季航次`）；导出清单 CSV 里也会带上这些属性列。

## 4. 在线查看器（与桌面版对齐）

- **双栏**：左=灰度（**不跑算法**，只受亮度/对比影响，悬停显示**原始值**）；右=算法链 + 伪彩（悬停显示**处理后的数值**）。
- **播放语义**（逐字对齐 `hdy_viewer.py`）：
  - 步长 `step = max(1, int(speed))`，间隔 `interval = max(40, int(180 / speed))` ms
  - 上一帧/下一帧会先暂停；播放到最后一帧自动停止；停止回到首帧
  - 倍速档位：0.25 / 0.5 / 1 / 2 / 4 / 8（在线版默认 1x，桌面版默认 0.25x）
- **算法链**：勾选即生效，执行顺序固定为「异常值截断 → 自适应亮度 → 自动对比拉伸 → Gamma 提亮 → CLAHE → 多尺度局部背景校正 → 扇形图映射」（与桌面版注册集一致，共 7 个；**有状态的"时间干扰抑制"不进在线版**）。
- **扇形映射**：把极坐标声呐数据重采样成扇形显示（伪彩栏画布会变宽，例如 256 → 2641 列），扇形外二次置黑；协议不提供波束角时自动禁用。
- **逐帧尺寸**：**每帧的画布尺寸可能不同**（Norbit 各 ping 的采样数随量程自动变化：帧 1 是 654×256，帧 101 是 1320×256）。查看器按每帧响应里的 `shapes` 实时摆放十字准星与换算悬停坐标，不依赖首帧尺寸。
- **悬停取值**：按栏上报 `panel=gray|color`，两栏各自在自己的坐标系里取值（灰度栏=原始像素 + 波束角；伪彩栏=处理后数值）。坐标越界服务端返回 422，不做静默钳制——避免"看着一个像素、显示另一个像素"的错值。
- **预取**：播放时一次批量取 32 帧（服务端渲染有缓存），前端缓冲；参数一变（伪彩/亮度/对比/算法/扇形）缓冲自动失效。
- 快捷键：空格=播放/暂停，←/→=单帧，Home/End=首末帧。

## 5. 配置项

**改配置就改一个文件：`data_asset_platform/platform.env`**（Windows 与 Linux **共用这一个文件**），改完保存、重启平台（Windows `scripts\start.bat`，Linux `scripts/start.sh`）即生效。文件里每一项都有中文注释，被注释掉的行就用内置默认值。换数据盘、换端口、换 Python 解释器都改它，**不用动代码，也不用在每个终端里 `set` 环境变量**。只有一处要跟着系统换：**路径写法**（`D:\data_platform\storage` ↔ `/srv/data_platform/storage`，`platform.env` 里有 Linux 示例）。

取值优先级（高 → 低）：

1. **当前终端里临时设的环境变量** —— 例：`set STORAGE_ROOT=E:\tmp`（Linux `export STORAGE_ROOT=/srv/tmp`）再启动，只影响这一个窗口
2. **`platform.env`**
3. **代码里的默认值**（`backend/app/config.py`）

想确认"现在到底用的是哪套值"：

```powershell
scripts\config.bat                # 全部，每一项都标了来源：环境变量 / platform.env / 默认值
scripts\config.bat storage_root   # 只看一项
```

```bash
scripts/config.sh                 # Linux 同款，输出完全一致
scripts/config.sh storage_root
```

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `STORAGE_ROOT` | `D:\data_platform\storage` | 存储根目录（实体文件按内容哈希存放，**换目录前先把旧目录整个拷过去**） |
| `DB_PATH` | `D:\data_platform\data\platform.db` | SQLite 文件（父目录会自动建） |
| `CACHE_DIR` | `D:\data_platform\cache` | 索引与缩略图缓存 |
| `BIND_HOST` / `BIND_PORT` | `0.0.0.0` / `8000` | 监听地址与端口（`0.0.0.0` = 局域网可访问，只想自己用就改 `127.0.0.1`） |
| `PYTHON_EXE` | （自动探测） | Python 解释器，`scripts\*.bat` 与 `scripts/*.sh` 都用 |
| `CHUNK_SIZE` | `8388608` | 上传分片大小（8MB） |
| `MAX_FILE_SIZE` | `10737418240` | 单文件上限（10GB） |
| `UPLOAD_SESSION_TTL_H` | `48` | 未活动上传会话过期小时数 |
| `CACHE_MAX_BYTES` | `268435456` | 帧图片内存缓存上限（256MB） |
| `SMALL_CACHE_MAX_BYTES` | `33554432` | 小尺寸帧的独立缓存上限 |
| `PLAYBACK_BASE_INTERVAL_MS` | `180` | 播放基准间隔（1x = 180ms/帧） |
| `PLAYBACK_MIN_INTERVAL_MS` | `40` | 最小间隔（8x = 40ms/帧） |
| `PLAY_BATCH_COUNT` / `PLAY_BATCH_MAX_COUNT` | `32` / `64` | 批量取帧默认/上限 |

| `READER_POOL_SIZE` | `8` | Reader 句柄池大小（按文件哈希复用） |

**格式约定**：一行一个 `键=值`，以 `#` 开头的行是注释，空行忽略。注释请**另起一行**（值里不要写 `#`）；值的**两边不要留空格**（`.bat` 读不出尾部空格），`键 = 值` 这种写法是可以的。值里可以有空格，例如 `PYTHON_EXE=C:\Program Files\Python\python.exe`。

**`platform.env` 放哪**：默认在工程根下。想放到别处（比如数据盘），设 `PLATFORM_ENV_FILE` 指向它，Python 和 `.bat` 都会跟着走：

```powershell
$env:PLATFORM_ENV_FILE = "D:\data_platform\platform.env"
```

**文件不存在会怎样**：直接用内置默认值，不影响启动——`platform.env` 是可选的。

**多个读取方，一份文件**：`STORAGE_ROOT` / `DB_PATH` / `CACHE_DIR` 及所有其它选项由 Python 读取（`backend/app/config.py`），启动脚本需要的少数几项按平台分别处理：

- **Windows `.bat`**：`scripts\_env.bat` 读 `PYTHON_EXE` / `BIND_HOST` / `BIND_PORT` 并导出成环境变量；
- **Linux `.sh`**：`scripts\_env.sh` 只读 `PYTHON_EXE`；端口、监听地址、数据目录它**不自己解析**，而是问 `scripts/show_config.py <键>` 拿解析结果。

两条路都建立在同一个前提上：Python **优先采用已设好的环境变量**，而且 `show_config.py` 走的就是 `config.py` 里的解析逻辑（含优先级）。所以不管谁去读，拿到的永远是同一套值，不会各算各的。

## 6. API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 健康检查 |
| GET/POST/PATCH/DELETE | `/api/attributes[/{id}]` | 属性库（可复用的**属性名**的增删改查）：**已有关联取值的属性禁删（409）**；名称即标识，重名冲突 409，名称含 `=`/`!` 返回 422 |
| GET | `/api/attributes/values?name=&limit=` | **属性已有的取值**（去重 + 计数，按出现次数降序）：填写/筛选时"直接选"而不是手敲；`name=` 只取一个属性（不存在 → 404），`truncated=true` 表示还有更多 |
| POST | `/api/attributes/resolve` | **批量"取或建"属性**，body `{"names": ["航次","海域"]}`：库里有则复用、没有才新建并保留（幂等）；返回 `created`/`existing` |
| GET/POST/PATCH/DELETE | `/api/templates[/{id}]` | 属性模板（必填/默认值/顺序） |
| POST | `/api/uploads/init` | 初始化上传（**同内容直接秒传**；同文件续传复用会话；`auto_create_attributes=true` 时未定义的属性名自动补建并保留） |
| PUT | `/api/uploads/{sid}/chunks/{i}` | 上传分片（裸二进制体，校验大小与序号） |
| GET/POST/DELETE | `/api/uploads/{sid}`、`/complete`、`/reset` | 进度 / 合并 / 重置 / 中止 |
| POST | `/api/import` | **服务端按路径导入**（文件或目录，可递归、可移动；同样支持 `attributes` + `auto_create_attributes`） |
| GET | `/api/files` | 组合检索（关键词/格式/大小/时间/状态/协议/`attr` 属性条件/排序/分页） |
| GET/PATCH/DELETE | `/api/files/{id}` | 详情 / 改名与挪目录 / 删除 |
| PUT | `/api/files/{id}/attributes` | 覆盖或增量写属性（`create_missing=true` 时未定义的属性名自动补建并保留；默认忽略未知属性名并在 `ignored_names` 里回报） |
| POST | `/api/files/{id}/parse` | 立即（重新）解析：协议识别 + 建帧索引 + 缩略图 |
| GET | `/api/files/{id}/download`、`/thumbnail` | 原始文件下载 / 列表缩略图 |
| GET | `/api/files/export.csv` | 文件清单 CSV（元数据表，带 BOM，Excel 可直接打开） |
| GET | `/api/sonar/algorithms` | 算法清单 + 伪彩清单 + 播放参数 |
| GET | `/api/sonar/{id}/info` | 查看能力探测（是否支持、协议、帧数、尺寸、是否可扇形映射） |
| GET | `/api/sonar/{id}/view?index=` | 单帧**双栏**（灰度 + 伪彩），可带算法链/伪彩/亮度/对比/扇形；响应含逐帧 `shapes.{gray,color}` |
| GET | `/api/sonar/{id}/frames?start=&count=&step=` | 批量取帧（播放用），每帧同样携带两栏与 `shapes` |
| GET | `/api/sonar/{id}/pixel?index=&x=&y=&panel=gray\|color` | 悬停取值：灰度栏=原始值+波束角，伪彩栏=处理后数值；坐标越界返回 422 |
| GET | `/api/sonar/{id}/frame/{index}.png?panel=gray\|color` | 单栏 PNG（带 ETag，支持 304） |
| GET | `/api/sonar/{id}/meta/{index}`、`/stats` | 单帧元数据 / 缓存与解析状态 |

属性筛选条件格式（`attr` 可重复，条件之间是"并且"）：普通属性**只有 `属性名=值`（等于）一种**，**值一律按字符串比较**；`!=`、`like:`、`in:`、`>`、`<` 这些写法都已取消（出现即 422，不会静默按字符串乱比）；属性名必须已在属性库里存在，否则 422。

**唯一例外是内置「日期」**，支持时间范围（值是定宽 `YYYY-MM-DD`，字符串比较即时间比较）：

```http
GET /api/files?attr=%E6%97%A5%E6%9C%9F%3E%3D2026-10-01   # 日期>=2026-10-01
GET /api/files?attr=日期>=2026-10-01&attr=日期<=2026-10-31  # 之间（两条一起）
```

- 只给一端就是单边限制；值必须是真实日期（`2026-02-30`、`乱写` → 422）。
- **普通属性用 `>=`/`<=` → 422**（`不支持时间范围比较`），不会退化成按字符串比大小。

## 8. 运维

```powershell
& $env:PYTHON_EXE scripts\check_storage.py           # 一致性检查：实体缺失/孤儿/引用计数
& $env:PYTHON_EXE scripts\check_storage.py --fix     # 修正引用计数并清理孤儿实体
& $env:PYTHON_EXE scripts\backup.py --dest E:\bak     # 数据库（在线备份）+ 帧索引 + 实体清单
& $env:PYTHON_EXE scripts\backup.py --dest E:\bak --with-blobs   # 连文件本体一起备份
```

- 文件本体用内容寻址：`storage/blobs/<sha256前2位>/<sha256><扩展名>`；多份同名/同内容文件**只落一份**，删除靠引用计数释放。
- **删除文件必须连同实体一起清掉**：删除前先放开本进程的读句柄（Windows 上被占用的文件删不掉，曾出现"库里查不到、磁盘上却永久留着"的孤儿大文件）。句柄仍被别的进程占着时，删不掉的实体**保留一条 `ref_count=0` 的记录**当作"待清理"标记，由服务/Worker 启动时与定期清理自动补删；`scripts\check_storage.py` 可随时查看，加 `--fix` 立即修正引用计数、清理孤儿实体与派生缓存（帧索引/缩略图）。
- 注册为 Windows 服务（可选）：用 [nssm](https://nssm.cc/) 分别把 `run_backend`（uvicorn）与 `run_worker` 注册为服务，日志用 `--log-config`/重定向到文件。
- 生产建议：`STORAGE_ROOT` 指向数据盘；`--workers 1` 即可（渲染无状态，多 worker 也能正确工作，只是各自多一份内存缓存）。

## 10. 已知限制

- 每个文件内部按“连续帧”处理；跨文件关联（如同一航次多文件拼帧）不在本期范围。
- **帧尺寸逐帧可变**（Norbit 各 ping 采样数随量程变化）。好处是忠实还原原始数据；代价是播放时画面会随帧缩放，属预期行为（桌面版同样如此）。
- 开启扇形映射后伪彩栏画布会显著变宽（长宽比与灰度栏不同），两栏不再像素对齐；这是桌面版的既有行为，平台保持一致。
- 帧渲染在**服务端**完成：单帧 ~6–15ms（654×256），1320×256 约 30ms。若未来出现 4000×4000 级数据，需要开启 `§12.1` 预案（预生成播放序列）。
- 浏览器端 sha256 计算仅对 ≤64MB 文件生效（大文件跳过，去重在服务端合并时按真实哈希完成）。
- 免构建页按**上传 / 数据查询 / 属性管理**三分页组织（「上传」页内再分两栏：左栏传、右栏属性），覆盖“传（多文件）+ 关联属性（**属性库复选框勾选即关联 +「复用上次」带值预填** / 缺失即新建 / **取值直接列在框下一排可点链接，没有的就手输**）+ 服务端导入 + 找（含属性条件，**取值可从已有取值里选**，**内置「日期」可按「从 / 到」时间范围筛**）+ 看 + 下载 + 属性库管理（查看使用条数 / 删除未被使用的属性；**内置「日期」标「（内置）」不可删**）”；属性模板管理、整目录选择上传等完整管理功能在 Vue 正式界面。
- **没有内置的“数据集/分类/标签”实体**：文件清单是平铺的，归属信息（数据集名、航次、海域…）一律用自建属性表达（见 §3.2）。因此检索条件里也没有数据集/分类/标签下拉，改用属性条件。
- 属性**被文件用过就不允许删除**（`DELETE /api/attributes/{id}` → 409）：这是为了避免“删了属性、文件上的值成了孤儿”。要删先清掉这些文件上的该属性值（文件详情页把值清空保存），或删除对应文件。
- **属性只有名称、值一律是字符串**（v1.6）：没有类型/单位/可选值，检索也只有 `等于/不等于/模糊匹配/属于` 四个字符串运算符（`>`/`<` 会明确报 422）。属性名里不能出现 `=` 和 `!`，否则 `attr=名称=值` 无法解析。
- Vue 正式界面需要 Node.js 构建（本机暂无 Node，代码已就绪但未经构建验证）；免构建页已在真实浏览器逐项验证通过。
- `scripts\*.bat` **必须保持纯 ASCII**：cmd 按当前代码页逐行解析批处理，含中文/全角标点的脚本会错位（标签行被当成命令、行被合并），实测即报 `'obrowse' 不是内部或外部命令` 这类错误。中文提示放在 README，脚本里只用英文。
- 一键启动脚本会新开两个窗口（后端、Worker）；关闭它们或执行 `scripts\stop.bat` 即可停止服务。
